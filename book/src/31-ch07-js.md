TypeScript is JavaScript with types added. So before the types, let's make sure the JavaScript underneath is solid. This chapter covers the features you'll see in every real codebase, plus the traps that catch even experienced developers.

!!! learn "What you'll learn"
    - `const`, `let` and template strings
    - Arrow functions and default parameters
    - Destructuring and the spread operator
    - `?.` and `??` (and why not `||`)
    - Array methods: `map`, `filter`, `find`, `reduce`...
    - `Map`, `Set`, dates, and money

Create a folder `ch07/` and a file `play.mjs`. Type each example in and run it with `node play.mjs`.

## 7.1 Variables: `const` first

```js
const businessName = "Glow Salon";   // can't be reassigned
let bookingCount = 0;                 // can be reassigned
bookingCount = bookingCount + 1;
```

**Use `const` by default.** Use `let` only when you really need to reassign. Never use `var` (it's the old way and has confusing rules).

!!! warning "`const` doesn't freeze objects"
    `const` stops you reassigning the *variable*, but you can still change what's inside an object or array:

    ```js
    const service = { name: "Haircut" };
    service.name = "Beard trim";  // ✓ allowed
    service = {};                 // ✗ TypeError: Assignment to constant variable.
    ```

### Template strings

Backticks let you put values inside strings with `${...}`:

```js
const name = "Ayesha";
const minutes = 45;
console.log(`Hi ${name}, your appointment lasts ${minutes} minutes.`);
console.log(`That's ${minutes / 60} hours.`);   // any expression works
```

## 7.2 Functions

```js
// Function declaration
function add(a, b) {
  return a + b;
}

// Arrow function: the same thing, shorter
const multiply = (a, b) => a * b;            // one expression: return is automatic

const greet = (name = "stranger") => {       // default parameter
  const message = `Hello, ${name}!`;
  return message;                            // with { } you need return
};

greet();          // "Hello, stranger!"
greet("Bilal");   // "Hello, Bilal!"
```

You'll see arrow functions most often as **callbacks**: functions you pass to other functions, like `prices.map((p) => p * 2)`.

## 7.3 Objects: destructuring and spread

### Destructuring: unpack values into variables

```js
const service = { name: "Haircut", priceCents: 150000, staff: { name: "Bilal" } };

const { name, priceCents } = service;
console.log(name, priceCents);           // Haircut 150000

// Rename, and give a default if the property is missing
const { name: serviceName, discount = 0 } = service;
console.log(serviceName, discount);      // Haircut 0

// Arrays destructure by position
const [first, second, ...rest] = [10, 20, 30, 40];
console.log(first, second, rest);        // 10 20 [ 30, 40 ]
```

Destructuring is very common in function parameters:

```js
function describe({ name, priceCents }) {
  return `${name}: ${priceCents / 100} PKR`;
}
describe(service);   // "Haircut: 1500 PKR"
```

### Spread: copy and combine

```js
const updated = { ...service, priceCents: 160000 };   // copy, then override one field
console.log(service.priceCents, updated.priceCents);  // 150000 160000

const allTags = [...["hair"], ...["beard", "color"]]; // [ 'hair', 'beard', 'color' ]
```

Creating a *new* object instead of changing the old one is called **immutability**. It makes code easier to reason about, because nothing changes behind your back.

!!! warning "Spread copies only one level deep"
    ```js
    const copy = { ...service };
    copy.staff.name = "Changed";
    console.log(service.staff.name);   // "Changed" (!)
    ```
    The inner `staff` object is **shared** between both copies. For a full deep copy, use `structuredClone(service)`.

## 7.4 Optional chaining `?.` and nullish coalescing `??`

```js
const booking = { customer: { name: "Sana" } };

booking.customer?.name;       // "Sana"
booking.staff?.name;          // undefined, instead of crashing
booking.staff.name;           // ✗ TypeError: Cannot read properties of undefined
```

`a?.b` means "if `a` is `null` or `undefined`, stop and give `undefined`; otherwise read `.b`".

`a ?? b` means "use `a`, unless it's `null` or `undefined`; then use `b`".

```js
const page = query.page ?? 1;
```

!!! mistake "`||` vs `??`"
    `||` falls back on **any falsy value**, including `0` and `""`. That's usually a bug:

    ```js
    console.log(0 || 10);     // 10  ← a discount of 0 became 10!
    console.log(0 ?? 10);     // 0   ← correct
    console.log("" || "none"); // "none"
    console.log("" ?? "none"); // ""
    ```
    Use `??` for defaults. Use `||` only when you really mean "any falsy value".

## 7.5 Truthy, falsy and `===`

In an `if`, these values count as **false**: `false`, `0`, `""`, `null`, `undefined`, `NaN`. **Everything else is true**, including `"0"`, `[]` and `{}`.

Always compare with `===` (strict equality). `==` converts types first and gives surprising results:

```js
0 == "";        // true  (!)
1 == "1";       // true
0 === "";       // false ✓
1 === "1";      // false ✓
```

## 7.6 Array methods

These replace most `for` loops in modern code. Learn them well: you'll use them every day.

```js
const prices = [1500, 800, 2500, 1200];

prices.map((p) => p * 2);              // [3000, 1600, 5000, 2400]  transform each item
prices.filter((p) => p >= 1200);       // [1500, 2500, 1200]        keep some items
prices.find((p) => p > 1000);          // 1500       first match (or undefined)
prices.findIndex((p) => p === 2500);   // 2          position of first match (or -1)
prices.some((p) => p > 2000);          // true       is there at least one?
prices.every((p) => p > 1000);         // false      are they all?
prices.includes(800);                  // true
prices.reduce((sum, p) => sum + p, 0); // 6000       combine into one value
```

| Method | Returns | Use when you want... |
|---|---|---|
| `map` | new array, same length | to transform every item |
| `filter` | new array, maybe shorter | only some items |
| `find` | one item or `undefined` | the first match |
| `some` / `every` | `true` / `false` | a yes/no question about the list |
| `reduce` | anything | to combine items into one value (total, count, object) |

### `reduce` step by step

`reduce` is the hardest one, so let's slow down. It walks through the array carrying an **accumulator** (a running result):

```js
const total = [1500, 800, 2500].reduce((sum, price) => sum + price, 0);
// start: sum = 0
// 1500 → sum = 0 + 1500 = 1500
// 800  → sum = 1500 + 800 = 2300
// 2500 → sum = 2300 + 2500 = 4800
```

It can also build objects, like counting bookings per staff member:

```js
const bookings = [{ staff: "Bilal" }, { staff: "Sana" }, { staff: "Bilal" }];

const perStaff = bookings.reduce((counts, b) => {
  counts[b.staff] = (counts[b.staff] ?? 0) + 1;
  return counts;
}, {});
// { Bilal: 2, Sana: 1 }
```

Modern JavaScript also has `Object.groupBy(bookings, (b) => b.staff)`, which groups items into lists.

!!! mistake "The `sort` trap"
    ```js
    [10, 9, 1, 100].sort();                  // [1, 10, 100, 9]  ← sorted as TEXT!
    [10, 9, 1, 100].sort((a, b) => a - b);   // [1, 9, 10, 100]  ✓
    ```
    Also, `sort()` **changes the original array**. Use `toSorted()` to get a sorted copy and leave the original alone.

### Chaining

Because these methods return arrays, you can chain them into a readable pipeline:

```js
const services = [
  { name: "Haircut", priceCents: 150000, active: true },
  { name: "Beard trim", priceCents: 80000, active: false },
  { name: "Hair colour", priceCents: 450000, active: true },
];

const activeNames = services
  .filter((s) => s.active)
  .toSorted((a, b) => a.priceCents - b.priceCents)
  .map((s) => s.name);
// [ 'Haircut', 'Hair colour' ]
```

## 7.7 `Map` and `Set`

A **`Map`** is a key-value store. It's like an object, but designed for lookups, and keys can be any type. You'll use one as an in-memory "database" in Phase 3.

```js
const services = new Map();
services.set("svc_1", { name: "Haircut" });
services.get("svc_1");    // { name: 'Haircut' }
services.has("svc_2");    // false
services.delete("svc_1");
services.size;            // 0
[...services.values()];   // all values as an array
```

A **`Set`** stores unique values. Duplicates are ignored:

```js
const tags = new Set(["hair", "beard", "hair"]);
tags.size;     // 2
[...tags];     // [ 'hair', 'beard' ]
```

## 7.8 Dates and money

```js
const start = new Date("2026-11-03T09:30:00Z");   // Z = UTC
start.toISOString();         // "2026-11-03T09:30:00.000Z"
start.getTime();             // 1793698200000 (milliseconds since 1 Jan 1970 UTC)
start.getUTCHours();         // 9
start.getUTCMonth();         // 10  ← months start at 0! January = 0, November = 10

const end = new Date(start.getTime() + 30 * 60 * 1000);   // add 30 minutes
end.toISOString();           // "2026-11-03T10:00:00.000Z"

Date.now();                  // current time in milliseconds
```

!!! idea "Store times in UTC, send them as ISO strings"
    Servers should store and compare times in UTC and send them as ISO strings (`"2026-11-03T09:30:00Z"`). Converting to the user's local time is a display concern. Book 2 covers time zones properly for Slotify.

!!! warning "Never store money as a decimal number"
    ```js
    console.log(0.1 + 0.2);   // 0.30000000000000004
    ```
    Computers can't store most decimal fractions exactly. Store money as **whole numbers of the smallest unit** (cents, paisa): PKR 1,500.00 is stored as `150000`. Divide by 100 only when displaying.

## 7.9 Classes, briefly

You'll mostly write plain functions and objects, but classes appear for things like custom errors:

```js
class Counter {
  count = 0;                 // a field with a starting value

  constructor(label) {
    this.label = label;
  }

  increment() {
    this.count += 1;
    return this.count;
  }
}

const c = new Counter("bookings");
c.increment();   // 1
c.increment();   // 2
```
